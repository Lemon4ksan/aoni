## Почему Aoni?

При интеграции с нестабильными API, парсинге или работе со сложными прокси-сетями на Go стандартный клиент `net/http` часто требует написания большого объема шаблонного кода для решения таких задач, как ротация прокси, лимиты запросов, устаревшие кодировки или TLS-фингерпринтинг. 

`aoni` устраняет этот барьер. Он представляет HTTP-запросы в виде конвейерных потоков, обрабатываемых декларативными **RequestModifiers** и стандартными **Go Middlewares**, используя дженерики для безопасного с точки зрения типов декодирования ответов. Движок остается непоколебимым под сетевой нагрузкой — прямо как синий они.

```shell
go get github.com/lemon4ksan/aoni
```

## Когда использовать Aoni вместо стандартных клиентов (например, Resty)

`aoni` не разрабатывался как замена `net/http` или легковесным оберткам вроде `resty` для обычных внутренних микросервисов, где единственная задача — максимальная пропускная способность при прямых и стабильных облачных соединениях.

* **Выбирайте `net/http` / `resty`** для: внутренних микросервисов, прямой интеграции с облачными API (AWS/S3, Stripe, Twilio) и стандартных высокопроизводительных REST API, где вы полностью контролируете целевой сервер и сетевое окружение.
* **Выбирайте `aoni`** для: обхода глубокого анализа пакетов (DPI), парсинга и сбора данных с ресурсов за агрессивными файрволами (Cloudflare, Akamai, Imperva), ротации нестабильных прокси-сетей со «липкими» (sticky) сессиями и работы с WebSockets в реальном времени поверх HTTP/2. Это ваша **тактическая внедорожная броня** для недружелюбных и хаотичных сетевых сред.

## Быстрый старт

```go
package main

import (
	"context"
	"fmt"
	"time"

	"github.com/lemon4ksan/aoni"
	"github.com/lemon4ksan/aoni/mod"
	"github.com/lemon4ksan/aoni/option"
	"github.com/lemon4ksan/aoni/request"
)

type User struct {
	ID   int    `json:"id"`
	Name string `json:"name"`
}

func main() {
	ctx := context.Background()

	// Устанавливаем глобальные параметры. Возвращается немутируемый склонированный клиент.
	client := aoni.NewClient(nil,
		option.WithBaseURL("https://api.example.com"),
		option.WithTimeout(15*time.Second),
		option.WithTLSFingerprint(aoni.BrowserChrome),
	)

	// Запрашиваем, валидируем и декодируем за один шаг
	user, err := request.GetTo[User](ctx, client, "/users/{id}",
		mod.WithVar("id", 123),
		mod.WithHeader("X-Custom-Header", "value"),
	)
	if err != nil {
		panic(err)
	}

	fmt.Printf("User: %s\n", user.Name)
}
```

## Декларативная конфигурация конвейера

`aoni` использует модульный конвейер запросов. Вы можете настроить этапы выполнения глобально с помощью `option.WithPipeline` или переопределить их для конкретного запроса через `WithPipeline`:

```go
resp, err := client.Get(ctx, "/path", mod.WithPipeline(aoni.PipelineConfig{
	RotateUA:   true,       // Согласованно ротирует User-Agent и Client Hints
	Decompress: true,       // Автоматически обрабатывает gzip, brotli и zstd
	Challenge:  true,       // Обнаруживает страницы проверки WAF (например, Cloudflare)
	Validate:   true,       // Запускает зарегистрированные валидаторы ответов
}))
```

`aoni` использует двухуровневую модель конфигурации: глобальные настройки по умолчанию задаются на уровне клиента, сохраняя при этом возможность точечно переопределять поведение транспорта для отдельных запросов с помощью контекстных модификаторов `RequestModifier`.

```
Параметры запроса -> Настройки по умолчанию клиента -> Системное окружение / Поведение транспорта
```

## Архитектура и подпакеты

```
aoni/
├── option/       // Опции инициализации клиента (option.With...)
├── mod/          // Модификаторы запросов (mod.With...)
├── request/      // Generic-хелперы (request.GetTo[T], PostTo, Concurrent)
├── cookie/       // Прокси-изолированные куки, JSON/SQL хранилища, импорт/экспорт Playwright
├── fingerprint/  // Обход TLS/JA4/p0f отпечатков, кадры HTTP/2, CDN-паддинг
├── netutil/      // Ротатор прокси, DoH/DoT DNS резолверы, ротатор IPv6 подсетей
├── codec/        // Декодеры ответов и кодирование структур в url.Values
├── realtime/     // WebSocket поверх H2 CONNECT, Socket.IO v5, SSE и NDJSON потоки
├── resiliency/   // Кэширование ответов, детекторы/солверы WAF, балансировщик нагрузки
└── telemetry/    // Генератор HAR, отслеживание задержек EWMA, локальный дашборд инспектора
```

## Распутывая магию

Стандартные HTTP-клиенты проектируются для статичных и дружелюбных сетей. `aoni` же работает на стыке сетевых протоколов, чтобы обходить глубокий анализ пакетов (DPI) и агрессивные файрволы.

> **Нужны примеры использования?**  
> Загляните в директорию [examples](examples), чтобы узнать, как работать с aoni, а также в [примеры обхода блокировок](examples/evasions), чтобы увидеть интеграцию клиента с эмуляторами браузера вроде Playwright.

> **Интересует физика сетевых процессов?**  
> Прочитайте наше подробное руководство: [**Демистификация Вуду (Demystifying the Voodoo)**](docs/VOODOO.md), чтобы понять, как `aoni` манипулирует состояниями HPACK, переопределяет размеры окон TCP на уровне ОС с помощью системных вызовов и внедряет хаотический паддинг (заполнение пакетов) без разрыва соединений.
