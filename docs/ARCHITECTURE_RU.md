# Архитектура и системный дизайн

В этом документе описана многоуровневая архитектура, границы пакетов, правила импортов и инварианты параллелизма и памяти репозитория `aoni`.

```text
    ┌──────────────────────────────────────────────────────────────────┐
    │                      Уровень 4: Публичный API                    │
    │   aoni (клиент net/http) • fast (fasthttp/H2/H3) • option • mod  │
    └─────────────────────────────────┬────────────────────────────────┘
                                      │
    ┌─────────────────────────────────▼────────────────────────────────┐
    │              Уровень 3: Политики, кодеки и расширения            │
    │   resiliency • cookie • codec • realtime • fingerprint • tunnel  │
    └─────────────────────────────────┬────────────────────────────────┘
                                      │
    ┌─────────────────────────────────▼────────────────────────────────┐
    │                Уровень 2: Движки и конвейер                      │
    │   internal/pipeline • internal/fast/h1/h2/h3 • internal/core     │
    └─────────────────────────────────┬────────────────────────────────┘
                                      │
    ┌─────────────────────────────────▼────────────────────────────────┐
    │              Уровень 1: Сетевые протоколы и ОС                   │
    │   internal/quic • internal/qpack • internal/sys                  │
    └──────────────────────────────────────────────────────────────────┘
```

## 1. Четырёхуровневая архитектура

Репозиторий разделён на четыре чётких уровня со строгой однонаправленной зависимостью: верхние уровни могут зависеть от нижних, но нижние уровни никогда не зависят от верхних.

### Уровень 4: Публичный API
Точки входа для прикладного кода:
- **`package aoni`**: Основной фасад HTTP-клиента (`aoni.Client`). 100% совместим с `net/http.RoundTripper`, стандартными контекстами и middleware экосистемы Go.
- **`package fast`**: Высокопроизводительный движок (`fast.Client`) на базе `fasthttp` с нативной поддержкой HTTP/2 и HTTP/3 для высоконагруженных сценариев и скрейпинга.
- **`package option`**: Опции конфигурации клиента при инициализации (`option.WithBaseURL`, `option.WithTimeout`, `option.WithChrome`).
- **`package mod`**: Модификаторы запроса, применяемые к конкретному вызову (`mod.WithHeader`, `mod.WithBearer`, `mod.WithJSON`).

### Уровень 3: Политики, кодеки и расширения
Изолированные пакеты с сетевой функциональностью:
- **`cookie`**: Хранилище cookie по стандарту RFC 6265bis и jar с изоляцией по прокси (`ProxyIsolatedJar`).
- **`codec`**: Типобезопасные декодеры JSON, XML, Protobuf и фрейминга gRPC-Web.
- **`resiliency`**: Повторные попытки (retry), backoff, circuit breaker, кэширование (RFC 9111) и хеджирование запросов.
- **`fingerprint`**: Профили эмуляции браузеров (Chrome, Firefox, Safari), хэширование JA4 и настройка TLS ClientHello.
- **`realtime`**: WebSockets, Server-Sent Events (SSE) и потоковый NDJSON.
- **`tunnel`**: Прокси SOCKS5, HTTP CONNECT и туннелирование MASQUE (RFC 9298).

### Уровень 2: Движки и конвейер исполнения
Внутренняя оркестрация запросов:
- **`internal/pipeline`**: 5-этапный конвейер middleware (pre-flight, мутация запроса, выполнение транспорта, post-flight, валидация ответа).
- **`internal/fast/h1engine`**: Пул сокетов и управление соединениями HTTP/1.1 на базе `fasthttp`.
- **`internal/fast/h2engine`**: Мультиплексирование HTTP/2 со сжатием HPACK и фреймингом.
- **`internal/fast/h3engine`**: Управление соединениями HTTP/3 и интеграция QPACK поверх QUIC.
- **`internal/core`**: Общие внутренние типы (`ModifierAtom`, политики повторов).

### Уровень 1: Сетевые протоколы и примитивы ОС
Низкоуровневые реализации протоколов и вызовы ядра:
- **`internal/quic`**: Чистая Go-реализация IETF RFC 9000 (QUIC) и RFC 9002 (управление перегрузкой). **Строго изолирована**: клиентские пакеты не импортируют QUIC напрямую.
- **`internal/qpack`**: Сжатие полей QPACK (RFC 9204) для HTTP/3.
- **`internal/sys`**: Привязка к ядрам процессора и опрос возможностей ОС.

## 2. Изоляция подсистем и правила импортов

Для сохранения прозрачности и защиты публичных API от протекания протокольных деталей установлены строгие правила:

### Правило 1: Изоляция QUIC
- `internal/quic` — это приватная реализация протокола.
- Ни `package aoni`, ни `package fast` не имеют права импортировать `internal/quic`.
- Конфигурация HTTP/3 клиента выполняется строго через `internal/fast/h3engine.NewClientFromSettings()`, принимающий высокоуровневые настройки из `fingerprint/h3.Settings`.
- За пределами `internal/quic` протокол импортируют только протокольные драйверы (`h3engine`, `x/webtransport`, `tunnel/masque`, `netutil/dns/doq`).

### Правило 2: Разделение двух движков
- `aoni.Client` (`net/http`) и `fast.Client` (`fasthttp`) независимы.
- `aoni` не импортирует `fast`.
- Оба движка используют единый атомарный примитив модификатора (`aoni.RequestModifier`) и контракты данных (`aoni.Request`, `aoni.Response`, `aoni.HTTPRequester`).

### Правило 3: Разделение опций клиента и модификаторов запроса
- **Опции клиента** живут строго в `package option` (`option.With...`) и настраивают `*aoni.Config`.
- **Модификаторы запроса** живут строго в `package mod` (`mod.With...`) и возвращают `aoni.RequestModifier` (`core.ModifierAtom`).
- Корневой пакет `aoni` содержит только канонические методы, конструкторы и фундаментальные интерфейсы.

## 3. Сравнение двух клиентов

| Характеристика | `aoni.Client` (Стандартный) | `fast.Client` (Высокоскоростной) |
| :--- | :--- | :--- |
| **Базовый движок** | `net/http` (`http.RoundTripper`) | `fasthttp` + нативный H2/H3 |
| **Совместимость** | 100% совместимость со stdlib | Специализированный высоконагруженный API |
| **Протоколы** | HTTP/1.1, HTTP/2 | HTTP/1.1, HTTP/2, HTTP/3 (Alt-Svc гонка) |
| **Модель памяти** | Стандартный сборщик мусора Go | Пулы буферов (`sync.Pool`) |
| **Тело ответа** | Поток (`io.ReadCloser`) | Поток или переиспользуемый буфер байт |
| **Назначение** | Микросервисы, REST API, универсальный HTTP | Скрейпинг больших объёмов, нагрузочное тестирование |

## 4. Инварианты параллелизма и памяти

### Неизменяемость (Immutability) клиентов
Экземпляры `Client` (`aoni.Client` и `fast.Client`) **строго неизменяемы** после создания:
- Все методы безопасны для одновременного вызова из произвольного числа горутин.
- Методы `client.With(opts...)` и `client.Clone()` создают новый независимый экземпляр `Client` с глубоким копированием конфигурации. Исходный клиент не мутируется.

### Жизненный цикл RequestBuilder
`RequestBuilder` (`client.R()`) переиспользуется через `sync.Pool`:
- **Не является потокобезопасным**: экземпляр создаётся, настраивается и выполняется строго внутри одной горутины.
- **Защита от повторного использования**: после вызова `Execute()` или `Release()` билдер выставляет флаг `consumed = true`. Любая последующая попытка вызова сразу возвращает ошибку `ErrBuilderConsumed`.

### Время жизни буферов в `fast.Client`
- `fast.Response` переиспользует буферы между запросами.
- Слайсы из `resp.BodyBytes()` или `resp.UnsafeBodyBytes()` валидны **только до завершения обработки запроса или вызова `resp.Close()`**.
- Для сохранения данных за пределы запроса вызывающий код обязан сделать копию через `bytes.Clone()` или использовать `resp.String()`.
